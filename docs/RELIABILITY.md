# Reliability and safety notes

- **Allocation:** one SQLite immediate transaction reserves one available agent and one eligible borrower. Rechecking availability inside the transaction handles agents who became unavailable before allocation.
- **Duplicate work:** allocation filters borrowers with active calls and safely requeued work. `claim_queued()` resumes a pre-provider reservation in place, preserving one call per borrower. This sample does not model legal contact windows or suppression lists.
- **Events:** `(provider, event_id)` is the idempotency key; `(call_id, provider, seq)` is unique. Repeated IDs return `DUPLICATE`; old sequence values return `STALE`; invalid transitions return `INVALID_TRANSITION`.
- **Safety:** predictive output is a proposal only. Safety applies configured rate/concurrency caps and pauses on stale/low-sample estimates or unhealthy providers. The abandonment estimate is a deliberately simple illustrative heuristic, not a regulatory calculation.
- **Provider failure:** new calls are allocated only when a mock provider is available. An outage does not automatically fail an already-ringing call; the provider event or timeout determines its outcome. Timed-out calls may enter `RETRY_WAIT` with one bounded retry and deterministic exponential backoff (5 seconds, then 10 seconds under the default policy). Retry claims reuse the same call and borrower while atomically reserving an available agent. Predictive pacing scales its proposal by provider health, and the Safety Controller pauses on unhealthy provider inputs. This is a local simulation policy, not a production retry scheduler.
- **Worker recovery:** `Store.recover()` requeues only calls still in `RESERVED`, because no provider attempt was started. Calls in `INITIATED`, `RINGING`, `ANSWERED`, or `CONNECTED` become `UNCERTAIN`; their agents are paused and borrowers remain protected until a late provider event reconciles the outcome. This avoids redialing a call that may already have reached a borrower. It is a local recovery hook, not process supervision or a distributed scheduler.
- **Load test:** `uv run python -m smartdialer.cli load-test --agents 32 --borrowers 32 --workers 16 --seed 42` races independent SQLite connections using temporary synthetic data. A pass means the expected number of unique reservations completed without worker exceptions. The reported rate varies with machine and filesystem and must not be read as production capacity.
- **Latest local smoke result:** 32/32 expected reservations, no duplicate borrower reservations, no worker errors; measured 1.098 seconds (about 29.14 reservations/second) in the latest local verification. This is one low-volume observation only.
- **Logs and privacy:** no names, phone numbers, email addresses, or raw dataset rows are logged. Only synthetic identifiers and aggregates should enter simulator output.
- **Limitations:** real-time contention, multi-host recovery, retention, provider callback authentication, timezone contact policy, opt-out/suppression enforcement, and compliance review are outside this prototype.
